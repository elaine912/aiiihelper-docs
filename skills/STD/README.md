# 軟體測試文件 (STD) 範本使用指南

軟體測試文件 (Software Test Document, STD) 是確保產品品質的核心文件。本指南將協助您有效利用 `template/STD.md` 進行測試規劃與執行。

---

## 1. 什麼是 STD？

STD 記錄了從測試規劃、案例撰寫到結果分析的完整過程。它不僅是品質保證 (QA) 的依據，也是開發團隊修復缺失、專案管理追蹤進度的重要參考。

## 2. 核心章節說明

### 2.1 測試目的與接受準則 (Objectives)
*   **系統範圍**：清楚界定本次測試涵蓋哪些模組（如：登入模組、醫師加入流程）。
*   **接受準則**：定義什麼情況下專案可以「過關」（例如：無高等級缺失、通過率達 100%）。

### 2.2 測試環境與資料 (Environment & Data)
*   **環境一致性**：詳列作業系統、瀏覽器、手機型號等，確保開發與測試環境一致。
*   **測試帳號**：預先準備不同權限的帳號（如：管理員、一般用戶），避免測試時因資料缺失而中斷。

### 2.3 測試案例 (Test Cases / BDD)
*   **情境導向 (BDD)**：建議採用行為驅動開發 (Behavior-Driven Development) 的思維，從使用者的角度出發。
*   **步驟清單**：精確描述操作流程，讓任何人（甚至非開發者）都能照著執行。
*   **預期結果**：同時包含「畫面呈現」與「資料庫變動」。

### 2.4 測試結果與缺失追蹤 (Results & Defect Tracking)
*   **透明化**：即時更新 Pass/Fail 狀態。
*   **缺失等級**：標註 High/Medium/Low，協助團隊決定修復優先順序。

### 2.5 追溯表 (Traceability Matrix)
*   **確保覆蓋率**：連結需求 (PRD/User Story) 與測試案例 (TC)，確保每一個功能需求都有對應的驗證機制，沒有遺漏。

---

## 3. 如何開始使用

1.  **複製範本**：將 `template/STD.md` 複製並放入專案的documentation資料夾中。
2.  **定義範疇**：首先填寫「系統範圍」與「測試資料」。
3.  **撰寫案例**：參考範本格式撰寫具體的 `TC-xxx`。
4.  **執行並紀錄**：在測試過程中，將結果填入「測試結果」與「缺失報告」章節。

---

## 4. 撰寫建議

*   **保持更新**：測試過程中若發現流程變動，應同步修改 STD。
*   **圖文並茂**：在「缺失說明」中，建議附上錯誤截圖連結或 Log 連結。
*   **回歸測試**：修復缺失後，務必重新執行受影響的測試案例。
