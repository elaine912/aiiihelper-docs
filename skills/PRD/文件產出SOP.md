### 步驟 1：取得資料 (準備實體檔案)

- **你的動作：** 去 GitHub 網頁點擊綠色按鈕 Download ZIP，並在 Mac 上解壓縮成**一個資料夾**。
- *(此步驟不需 AI)*

### 步驟 2：產出地圖 (取得 tree.txt)

- **開一個乾淨的終端機**
- **輸入 cd 並空一格（超級關鍵❗）**
    
    在新的終端機裡面，輸入 cd，然後**一定要按一下鍵盤的空白鍵**。（畫面上看起來會是 cd）。
    
- **把資料夾拖進去**
    
    用滑鼠把你解壓縮出來的**「程式碼資料夾」**，直接拖曳拉進終端機那個黑畫面裡面，然後放開滑鼠。*(這時終端機會自動幫你打上一長串的路徑，例如 /Users/你的名字/Downloads/xxx-code)*。
    
    接著，**按下 Enter 鍵**。*(這一步就是告訴終端機：請走進這個房間裡！)*
    
- **貼上指令**
    
    請把下面這整行綠色的字複製，貼到終端機裡，按下 **Enter**。
    
    <aside>
    
    find . -type f -not -path '*/\.*' -not -path '*/node_modules/*' > tree.txt
    
    </aside>
    
- *(此步驟不需 AI)*

### 步驟 3：AI 尋路 (讓 DeepSeek 幫你找檔案)

- **你的動作：** 打開 **Open Code (DeepSeek)**，準備好 tree.txt 以及你要寫的「某一個 BRD 模組（例如：結帳模組）」。

💬 **請複製以下 Prompt 貼給 DeepSeek：**

```markdown
你現在是一位資深的系統架構師 (Technical Architect)。我是一位不寫程式的 PM。
我需要從現有的程式碼中，反向推導出系統實際運作的邏輯。為了避免 Token 超載，我們將分模組進行。

以下是我們系統完整的【目錄結構樹】：
[請在此貼上 tree.txt 的全部內容]

現在我們專注於 BRD 中的這個功能模組：
【請在此貼上該模組的 BRD 說明，例如：結帳與購物車模組】

請根據上述目錄結構與 BRD 需求，告訴我：
「我應該把哪幾個檔案的完整程式碼提供給你，你才能看懂這個模組的完整業務邏輯？」

要求：
1. 必須包含核心的 Controller（控制器）、Service（服務層邏輯）、Model（資料庫模型），以及可能用到的共用工具檔 (Utils/Helpers)。
2. 排除無關的前端 UI 渲染檔或不相關的模組。
3. 請直接列出「檔案路徑清單」即可，不需要解釋太多，我會去把這些檔案複製給你。
```

### 步驟 6：逆向分析 (讓 DeepSeek 產出 CodeGraph)

- **你的動作：** 帶著剛剛複製好的程式碼，回到 **Open Code (DeepSeek)** 的同一個對話框。

💬 **請複製以下 Prompt 貼給 DeepSeek：**

```markdown
你現在切換角色為資深系統分析師 (System Analyst)。
我們即將針對系統進行功能疊加或異動（未來會導入 BRD 的需求）。
但在這之前，我需要你幫我把這塊功能【目前的現狀 (As-Is)】徹底梳理清楚。

以下是我從現有 Repo (Current Code) 中提取出來的相關檔案內容：
[請在此貼上 combined_code.txt 複製出來的全部程式碼]

請幫我執行以下兩項任務：

【任務一：依賴防漏檢查】
請先掃描上述程式碼，評估這塊功能的「現有核心邏輯」是否有缺漏？
是否有關鍵的「外部模組呼叫」或「重要函數」是我沒有提供給你的？
- 如果有，請暫停任務二，先告訴我：「你還需要補充提供 XXX 檔案，現狀邏輯才會完整」。
- 如果沒有缺失，請直接執行任務二。

【任務二：產出【現有系統邏輯圖 (As-Is CodeGraph)】】
這份 CodeGraph 的目的是讓我（PM）了解「系統現在到底怎麼跑的」，請把程式碼翻譯成白話業務邏輯，並使用結構化的 Markdown 輸出。
必須包含以下重點：
1. 核心流程 (Current API/User Flow)：目前這段程式碼的執行步驟是什麼？（例如：收到請求 -> 驗證 A -> 讀取 B -> 寫入 C）。
2. 現有資料實體 (Current Data Schema)：目前的邏輯讀取、寫入了哪些資料庫 Table？核心欄位有哪些？
3. 現有業務規則 (Current Business Rules)：現有的程式碼裡，已經寫了哪些驗證機制、計算公式或限制條件？（例如：現有的密碼長度限制、現有的庫存扣除邏輯）。
4. 外部依賴 (External Integrations)：這段程式碼目前有沒有呼叫外部第三方服務（如金流 API、寄信服務）？
```

*(💡 萬一 DeepSeek 回答你「還缺了 XXX 檔案」，你就去 GitHub 把那個檔案複製下來，貼給它說：「這是補充的 XXX 檔案程式碼，請繼續執行任務二」。)*
